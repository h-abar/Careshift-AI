# Event-Based Claims — المطالبة مبنية مما عاشه المريض فعلًا

> Careshift does not write claims from reports after the fact. A claim is
> **assembled** from the patient's timestamped clinical events. Every claim
> line points to the real events that justify it — who did what, when, and
> why. Nothing enters a claim that does not exist as an event.
>
> كيرشيفت لا يكتب المطالبة من تقارير لاحقة — بل **يجمّعها** من أحداث
> المريض السريرية المؤرشفة زمنيًا. كل سطر يشير إلى الأحداث الحقيقية التي
> تبرره. لا شيء يدخل المطالبة دون حدث مقابل.

## Data model — نموذج البيانات

- `ClinicalEvent` (append-only): `patientId`, `encounterId`
  (`enc-<patientId>` — the demo models one encounter per patient), `type`,
  `occurredAt` (when it happened), `recordedAt` (when it was recorded),
  `actorUserId`, `actorRole`, `payloadJson` (coded values — LOINC/RxNorm/
  ICD-10-AM/SBS only when imported from official lists), `sourceRecordId`,
  `ruleId`+`ruleVersion` when generated by a KB rule, `prevHash`, `hash`,
  `correctsId`, `correctionReason`, `lateEntry`.
- **Append-only contract** (`lib/server/events.ts`): no update/delete path
  exists in app code. A correction is a NEW event whose `correctsId` points
  at the corrected one, with a mandatory reason.
- **Hash chain**: each event's `hash = sha256(prevHash + canonical content)`
  per patient, so tampering breaks the chain. Verify offline:
  `npx tsx scripts/verify-events.ts`.
- **Late entries**: `recordedAt − occurredAt` beyond `LATE_ENTRY_MINUTES`
  (prototype setting, env-configurable) sets `lateEntry=true`.
- **Backfill** (`lib/server/backfill-events.ts`): converts existing vitals,
  risk assessments, interventions, handoffs and claim history into
  hash-chained events so legacy rows join the same ledger.
- `ClaimLine`: code + code system + **code version** (SBS version kept for
  NPHIES SBS-v3 readiness), quantity, service dates, `eventIdsJson`,
  `necessityJson` (compact evidence chain), `eventBacked`, `manualReason`,
  `flagsJson`. `InsuranceClaim` gained `nphiesCode`, `version`,
  `supersedesId` for denial/resubmission versioning.

## Mapping rules — قواعد الربط

Claim assembly (`lib/server/claim-assembly.ts`) applies **approved** KB
rules of category `claim-map` (`knowledge/seed/rules.json`). Each rule maps
event types/codes to a claim-line template. Tariffs come from
`knowledge/tariffs-simulated.json` — **Simulated sample prices only; no
real SBS tariffs are used or invented.**

Hard rule: **no events → no line.** A manual line requires a reason and is
persistently flagged `eventBacked=false`. Diagnoses must be supported by a
physician `documentation_entry` event carrying the diagnosis code or they
are flagged.

## Consistency checks — فحوص الاتساق (C4)

`runClaimChecks` checks both directions and **never auto-changes codes**:

| Direction | Check |
|---|---|
| Billed-not-lived | line without events, quantity > events support, level of care > events support |
| Lived-not-billed | events that map to a service but have no line (under-billing) |
| Documentation gaps | mapped to **official NPHIES adjudication-reason codes** imported into `Terminology` |
| Timing | service dates outside the encounter, events recorded after claim creation, late entries |

Output: `readiness %` + issue list. All checks are rule-based and labeled
"Rule-based checks, prototype".

## Insurer package — حزمة التأمين (C5)

`GET /api/claims/:id/package` returns a **minimum-necessary** read-only
package: claim lines + per-line event summaries (type, time, actor role,
coded value) — not the full chart, **no patient names**. Includes event
hashes and a package hash; `?verify=1` re-computes and detects tampering.
Exports: FHIR-style JSON (`Claim` + `supportingInfo` referencing events)
and a minimal PDF. Every package generation is audited (PDPL
need-to-know).

## Denial & appeal — الرفض والاستئناف (C6)

`POST /api/claims/:id/adjudicate` runs the **simulated payer**: it denies
with the first issue's **official NPHIES code** (imported list only —
never invented) or approves a clean claim. For a denial,
`GET /api/claims/:id/appeal-evidence` shows which event types are missing
and which existing events already answer the code. The appeal package may
reference **existing patient events only** — fabricated or foreign event
ids are rejected (422), and the appeal is clinician-approved + audited.
Resubmission creates a **new claim version** (`<id>-v2`) linked via
`supersedesId`; the denied original is never rewritten.

## KPIs — المؤشرات (C7)

`GET /api/kpis/claims` computes from the registry: % event-backed lines,
first-pass acceptance (Simulated), denials by NPHIES category, mean
readiness, billed-not-lived / lived-not-billed counts, late-entry %, and
mean event→claim lag (prototype discharge→claim proxy — no discharge
timestamp is modelled). KPI definitions live in the `KpiDefinition`
registry (`knowledge/seed/rules.json`).

## Limitations — الحدود

- Tariffs are **Simulated samples**; no real SBS pricing is claimed.
- The payer is **simulated** — NPHIES calls are made only via the C10
  module, and only to a configured sandbox. See `docs/nphies-integration.md`.
- SBS / ICD-10-AM / medication code lists are **imported fragments**;
  terminology coverage is partial and missing codes are flagged, never
  guessed.
- All patient data is synthetic and labeled Simulated.
